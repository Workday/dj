# DJ MCP Server

Agent-agnostic stdio MCP server for DJ (Data JSON) model workflows.

JSON (`.model.json` / `.source.json`) is the **source of truth**. Sibling `.sql` / `.yml` are generated by headless DJ logic — **no VS Code extension required**.

Two project modes:

1. **Production catalog** — operator configures 2–3 dbt repos; users pick `project-a` / `project-b`.
2. **Independent local** — `dj_use_local_project` with a local path.

Create/update runs in an isolated git worktree until `dj_ship`.

## Agent happy path

1. `dj_list_projects` → `dj_use_project`
2. `dj_create_source` / `dj_create_model` (JSON → sql/yml)
3. `dj_preview_data` (compile + defer) and/or `dj_get_lineage`
4. User: **“run model”** → `dj_run_model` → agent asks upstream vs defer → run + Trino preview
5. User: **“create PR”** → `dj_review_change` → `dj_ship({ approval: true, commitMessage })`

## Tools

| Tool | Purpose |
|------|---------|
| `dj_list_projects` | List catalog / local projects |
| `dj_use_project` | Select catalog `projectId` |
| `dj_use_local_project` | Select local checkout |
| `dj_describe_structure` | Groups/topics + naming |
| `dj_list_models` / `dj_get_model` / `dj_validate_model` | Inspect / validate |
| `dj_preview_model` | Artifact SQL/YAML only |
| `dj_create_model` / `dj_update_model` | JSON SoT → sql/yml (change set) |
| `dj_create_source` | Source JSON → yml |
| `dj_create_e2e` | Requirement → create + preview + lineage |
| `dj_get_lineage` | Upstream/downstream graph |
| `dj_trino_status` / `dj_list_trino_tables` / `dj_preview_source` | Trino browse / sample |
| `dj_preview_data` | Compile (or run) + Trino sample; defer by default |
| `dj_run_model` | **Run model** — ask/defer/build upstream, write Trino, preview |
| `dj_review_change` | Status + **diff** before PR |
| `dj_ship` | **Create PR** — commit / push / `gh pr create` |
| `dj_discard_change` | Revert change set |
| `dj_publish_change` | Legacy alias of `dj_ship` |

## CLI (`dj-gen`)

Same headless generators, no MCP:

```bash
cd dj && npm run mcp:build
node mcp/dist/cli.js generate model --project /path/to/dbt --json model.model.json --write
node mcp/dist/cli.js validate model --json model.model.json
node mcp/dist/cli.js preview-artifacts --project /path/to/dbt --json model.model.json
```

Bin name after link: `dj-gen`.

## Setup

```bash
cd dj
npm install
npm run mcp:build
```

Copy [`config.example.json`](config.example.json) → `~/.dj-mcp/config.json` or set `DJ_MCP_CONFIG`.

Prefer [`start.sh`](start.sh) as Cursor `command` so shell env (`TRINO_PASSWORD`, `DJ_DBT_PATH`) loads.

### Trino + dbt

```json
{
  "trino": {
    "enabled": true,
    "host": "trino.example.com",
    "port": 443,
    "catalog": "glue_development",
    "schema": "your_schema",
    "user": "coder",
    "passwordEnv": "TRINO_PASSWORD",
    "previewMode": "compile"
  }
}
```

Env: `TRINO_PASSWORD`, `DJ_DBT_PATH`, `DBT_PROFILES_DIR`, `DJ_DBT_DEFER_SCHEMA` (default shared upstream schema, e.g. `datamarts_portal`).

### `dj_run_model` upstream choice

| `upstream` | Behavior |
|------------|----------|
| `ask` (default) | Returns `needsDecision` — agent asks the user |
| `defer` | `dbt run --select model --defer` → shared schema upstreams |
| `build` | `dbt run --select +model` — rebuild chain in your schema |

Then samples `SELECT * FROM catalog.schema.model LIMIT N`.

### Ship / PR

1. `dj_review_change({ changeSetId })` — show diff
2. `dj_ship({ changeSetId, approval: true, commitMessage })` — branch, push, PR

Requires `git` + authenticated `gh`.
